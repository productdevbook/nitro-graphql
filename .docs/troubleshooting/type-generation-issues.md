# Type Generation Issues

Troubleshooting TypeScript type generation problems in Nitro GraphQL.

## Types Not Generating

### Problem: Type files not created or empty

**Symptoms:**
- Missing `.nitro/types/nitro-graphql-server.d.ts`
- Missing `.nitro/types/nitro-graphql-client.d.ts`
- Import errors for `#graphql/server` or `#graphql/client`

**Common Causes:**
1. Dev server not running
2. No schema or query files found
3. Type generation disabled in config
4. File permissions issues

**Solutions:**

1. **Start Dev Server:**
Type generation happens automatically when dev server starts:
```bash
pnpm dev
```

Look for console output:
```
✔ Generated server types at .nitro/types/nitro-graphql-server.d.ts
✔ Generated client types at .nitro/types/nitro-graphql-client.d.ts
```

2. **Verify Schema Files Exist:**
```bash
# Check for schema files
find server/graphql -name "*.graphql"

# At least one Query type should exist
```

3. **Check Configuration:**
```typescript
// nitro.config.ts
export default defineNitroConfig({
  graphql: {
    types: {
      enabled: true, // ✅ Should be true or omitted (default: true)
      server: true,  // Generate server types
      client: true   // Generate client types
    }
  }
})
```

4. **Check File Permissions:**
```bash
# Ensure build directory is writable
chmod -R 755 .nitro .nuxt
```

5. **Force Regeneration:**
```bash
# Remove build directory
rm -rf .nitro .nuxt

# Restart dev server
pnpm dev
```

**Prevention Tips:**
- Always run dev server during development
- Ensure at least one schema file exists
- Don't disable type generation unless intentional
- Add build directories to `.gitignore`

## Outdated Types

### Problem: Types don't match current schema

**Symptoms:**
- TypeScript errors after schema changes
- Old field names still showing in autocomplete
- Type mismatches in resolvers

**Common Causes:**
1. Types not regenerated after changes
2. TypeScript server cache
3. IDE not picking up changes
4. Build cache issues

**Solutions:**

1. **Trigger Type Regeneration:**
```bash
# Save schema file to trigger watch
# Or restart dev server
pnpm dev
```

2. **Restart TypeScript Server (VS Code):**
```
Cmd+Shift+P (Mac) or Ctrl+Shift+P (Windows/Linux)
> TypeScript: Restart TS Server
```

3. **Clear Build Cache:**
```bash
rm -rf .nitro .nuxt node_modules/.cache
pnpm dev
```

4. **Verify Type Generation:**
Check the generated type file:
```bash
# View generated server types
cat .nitro/types/nitro-graphql-server.d.ts

# Look for your recent changes
```

5. **Check File Watcher:**
Ensure file watching is working:
```bash
# Console should show:
ℹ Schema changed, regenerating types...
```

**Prevention Tips:**
- Monitor console for type generation messages
- Restart TS server after major schema changes
- Use hot reload during development
- Clear cache periodically

## Import Errors

### Problem: Cannot import from virtual modules

**Symptoms:**
```typescript
// Error: Cannot find module '#graphql/server'
import type { Resolvers } from '#graphql/server'

// Error: Cannot find module '#graphql/client'
import type { GetUserQuery } from '#graphql/client'
```

**Common Causes:**
1. Types not generated yet
2. TypeScript configuration missing
3. Wrong import path
4. Build process incomplete

**Solutions:**

1. **Verify Types Generated:**
```bash
# For Nitro
ls -la .nitro/types/

# For Nuxt
ls -la .nuxt/types/

# Should see:
# nitro-graphql-server.d.ts
# nitro-graphql-client.d.ts
```

2. **Check Import Paths:**
```typescript
// ✅ Correct - Virtual imports
import type { Resolvers } from '#graphql/server'
import type { GetUserQuery } from '#graphql/client'

// ❌ Wrong - Don't use relative paths
import type { Resolvers } from './.nitro/types/nitro-graphql-server'
```

3. **Verify TypeScript Configuration:**

For Nitro projects:
```json
// tsconfig.json
{
  "extends": "./.nitro/types/tsconfig.json"
}
```

For Nuxt projects (auto-configured):
```json
// Auto-generated by Nuxt
{
  "extends": "./.nuxt/tsconfig.json"
}
```

4. **Restart IDE:**
Sometimes a full IDE restart is needed:
```bash
# Close and reopen your IDE
# Or restart the TypeScript language server
```

5. **Manual Type Reference (Temporary):**
If virtual imports still don't work:
```typescript
// Add to your file temporarily
/// <reference types="./.nitro/types/nitro-graphql-server.d.ts" />
```

**Prevention Tips:**
- Use proper TypeScript configuration
- Keep IDE and extensions updated
- Restart TS server after type generation
- Don't commit build directories to git

## Type Mismatch Errors

### Problem: Generated types don't match implementation

**Symptoms:**
```typescript
// Type error: Resolver return type doesn't match schema
export const userQueries = defineQuery({
  user: async (_, { id }) => {
    return { id, name: 'John' } // Type error here
  }
})
```

**Common Causes:**
1. Schema and resolver out of sync
2. Nullable fields not handled
3. Return type doesn't match schema type
4. Context type mismatch

**Solutions:**

1. **Check Schema Definition:**
```graphql
# schema.graphql
type Query {
  user(id: ID!): User # Returns User, not User!
}

type User {
  id: ID!
  name: String!
  email: String! # Required field
}
```

2. **Match Return Type:**
```typescript
// ✅ Correct - includes all required fields
export const userQueries = defineQuery({
  user: async (_, { id }) => {
    return {
      id,
      name: 'John',
      email: 'john@example.com' // Include all required fields
    }
  }
})

// ❌ Wrong - missing required field
export const userQueries = defineQuery({
  user: async (_, { id }) => {
    return {
      id,
      name: 'John'
      // Missing email field
    }
  }
})
```

3. **Handle Nullable Fields:**
```graphql
# If field can be null, mark it optional
type Query {
  user(id: ID!): User # Can return null
}
```

```typescript
export const userQueries = defineQuery({
  user: async (_, { id }) => {
    const user = await db.user.findUnique({ where: { id } })
    return user // Can be null
  }
})
```

4. **Use Generated Types:**
```typescript
import type { Resolvers } from '#graphql/server'

export const userQueries: Resolvers['Query'] = {
  user: async (_, { id }, context) => {
    // TypeScript will enforce correct return type
    return await context.db.user.findUnique({ where: { id } })
  }
}
```

**Prevention Tips:**
- Use generated types for type safety
- Keep schema and resolvers in sync
- Handle nullable fields explicitly
- Use TypeScript strict mode

## Missing Types for External Services

### Problem: Types not generated for external GraphQL APIs

**Symptoms:**
```typescript
// Error: Cannot find module '#graphql/client/github'
import type { GetReposQuery } from '#graphql/client/github'
```

**Common Causes:**
1. External service not configured
2. Schema URL unreachable
3. Missing authentication headers
4. No query files for service

**Solutions:**

1. **Verify External Service Configuration:**
```typescript
// nitro.config.ts
export default defineNitroConfig({
  graphql: {
    externalServices: [
      {
        name: 'github', // ✅ Service name
        schema: 'https://api.github.com/graphql',
        endpoint: 'https://api.github.com/graphql',
        headers: () => ({
          Authorization: `Bearer ${process.env.GITHUB_TOKEN}`
        }),
        documents: ['app/graphql/github/**/*.graphql'] // ✅ Query files
      }
    ]
  }
})
```

2. **Create Query Files:**
```graphql
# app/graphql/github/repos.graphql
query GetRepos($owner: String!) {
  user(login: $owner) {
    repositories(first: 10) {
      nodes {
        name
        description
      }
    }
  }
}
```

3. **Check Schema Access:**
```bash
# Test if schema URL is accessible
curl -H "Authorization: Bearer YOUR_TOKEN" \
  https://api.github.com/graphql
```

4. **Verify Environment Variables:**
```bash
# Check token is set
echo $GITHUB_TOKEN

# Or in .env file
cat .env | grep GITHUB_TOKEN
```

5. **Check Generated Types:**
```bash
# Should see external service types
ls .nitro/types/

# Look for:
# nitro-graphql-client-github.d.ts
```

**Prevention Tips:**
- Document required environment variables
- Test external service connectivity
- Keep authentication tokens secure
- Create example .env.example file

## Context Type Errors

### Problem: Context properties not recognized by TypeScript

**Symptoms:**
```typescript
// Error: Property 'db' does not exist on type 'H3EventContext'
const user = await context.db.user.findUnique()
```

**Common Causes:**
1. Context types not defined
2. Context file not imported
3. TypeScript server not aware of augmentation
4. Module declaration issues

**Solutions:**

1. **Define Context Types:**
```typescript
// server/graphql/context.ts
import type { H3Event } from 'h3'

declare module 'h3' {
  interface H3EventContext {
    db: Database
    user?: User
    session?: Session
  }
}
```

2. **Import Context Augmentation:**
```typescript
// server/graphql/config.ts
import './context' // ✅ Import to ensure types are loaded

export default defineGraphQLConfig({
  // ...
})
```

3. **Use Context in Resolvers:**
```typescript
import type { Resolvers } from '#graphql/server'

export const userQueries: Resolvers['Query'] = {
  user: async (_, { id }, context) => {
    // context.db is now typed correctly
    return await context.db.user.findUnique({ where: { id } })
  }
}
```

4. **Restart TypeScript Server:**
After defining context types:
```
Cmd+Shift+P > TypeScript: Restart TS Server
```

**Prevention Tips:**
- Define all context properties upfront
- Use TypeScript interfaces for context types
- Import context file in config
- Document context properties in comments

## Cache Issues

### Problem: Old types persist despite regeneration

**Symptoms:**
- Old type definitions showing
- Changes not reflected
- Duplicate type declarations

**Common Causes:**
1. Multiple TypeScript servers running
2. Build cache corruption
3. Node modules cache
4. Editor cache

**Solutions:**

1. **Clear All Caches:**
```bash
# Remove build directories
rm -rf .nitro .nuxt

# Clear Node modules cache
rm -rf node_modules/.cache

# Clear pnpm cache (optional)
pnpm store prune

# Restart
pnpm dev
```

2. **Restart TypeScript Server:**
```
Cmd+Shift+P > TypeScript: Restart TS Server
```

3. **Restart IDE:**
Close and reopen your editor completely.

4. **Check for Multiple Processes:**
```bash
# Kill all node processes (Mac/Linux)
pkill -f node

# Or check running processes
ps aux | grep node
```

5. **Verify Clean Regeneration:**
```bash
# Check modification time of type files
ls -la .nitro/types/

# Should be recent timestamp
```

**Prevention Tips:**
- Clear cache regularly during development
- Close unused dev servers
- Restart IDE after major changes
- Don't run multiple instances

## Custom Scalar Types

### Problem: Custom scalars not typed correctly

**Symptoms:**
```typescript
// DateTime scalar treated as 'any'
const createdAt: Date = user.createdAt // Type error
```

**Common Causes:**
1. Scalar types not defined in codegen
2. Missing scalar implementations
3. Type mapping not configured

**Solutions:**

1. **Define Scalar Types in Config:**
```typescript
// nitro.config.ts
export default defineNitroConfig({
  graphql: {
    // Custom scalar type mappings
    scalars: {
      DateTime: 'Date',
      JSON: 'Record<string, any>',
      Upload: 'File'
    }
  }
})
```

2. **Use GraphQL Scalars Package:**
```bash
pnpm add graphql-scalars
```

```typescript
// server/graphql/config.ts
import { DateTimeResolver, JSONResolver } from 'graphql-scalars'

export default defineGraphQLConfig({
  resolvers: {
    DateTime: DateTimeResolver,
    JSON: JSONResolver
  }
})
```

3. **Define in Schema:**
```graphql
# server/graphql/scalars.graphql
scalar DateTime
scalar JSON
```

4. **Type Mapping in Codegen:**
The module automatically includes common scalars, but you can customize:
```typescript
// Handled automatically by nitro-graphql
// DateTime -> Date
// JSON -> Record<string, any>
```

**Prevention Tips:**
- Use standard scalar libraries
- Document custom scalars
- Keep scalar implementations consistent
- Map scalars to appropriate TypeScript types

## Federation Type Issues

### Problem: Federated schema types not generating

**Symptoms:**
- Missing types for federated entities
- Reference types not working
- Subgraph types incomplete

**Common Causes:**
1. Federation directives not in schema
2. Incorrect Apollo Federation setup
3. Type generation not supporting federation
4. Missing @key directives

**Solutions:**

1. **Add Federation Directives:**
```graphql
# server/graphql/schema.graphql
extend schema
  @link(url: "https://specs.apollo.dev/federation/v2.3", import: ["@key", "@external"])

type User @key(fields: "id") {
  id: ID!
  name: String!
}
```

2. **Configure Apollo Server:**
```typescript
// nitro.config.ts
export default defineNitroConfig({
  graphql: {
    framework: 'apollo-server', // ✅ Use Apollo for federation
  }
})
```

3. **Use Subgraph Schema Builder:**
```typescript
// server/graphql/config.ts
import { buildSubgraphSchema } from 'nitro-graphql/utils/apollo'

export default defineGraphQLConfig({
  // Federation-specific config
})
```

4. **Verify Entity Resolvers:**
```typescript
export const userResolvers = defineType('User', {
  __resolveReference: async (reference) => {
    return await db.user.findUnique({ where: { id: reference.id } })
  }
})
```

**Prevention Tips:**
- Use proper federation directives
- Test subgraph schema composition
- Keep entity resolvers updated
- Follow Apollo Federation best practices
